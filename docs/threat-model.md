# Sanad Threat Model

Pursuant to Section 4 of the Master Build Prompt, this document formalizes the threat vectors, security mitigations, and residual risks for the Authenticity Validator platform.

Each vector marked with **[Automated Test]** corresponds to a dedicated automated test suite residing in `backend/tests/threats/`.

---

| # | Attack Vector | Mitigation in Code | Automated Test | Residual Risk |
|---|---------------|--------------------|----------------|---------------|
| **1** | **Forger edits marks or dates on a genuine paper certificate** | **Road A**: Signature recomputation over RFC 8785 canonical bytes fails immediately on 1-bit change.<br>**Road B**: Extracted fields mismatch registry record; forensic analysis detects font/glyph/noise anomalies. | `test_threat_01_tampered_payload_fails_signature.py` | A flawless physical forgery with no corresponding registry record cannot be proven false, only classified as unverifiable (`CANNOT_VERIFY`). |
| **2** | **Fake QR code that points to attacker's lookalike website** | QR carries certificate ID and signature payload; client verifier app checks the signature itself and verifies against the canonical domain; printed PDF includes short plain-text URL. | `test_threat_02_canonical_domain_and_qr_payload.py` | A human verifier who scans the QR code with a generic phone camera and ignores the browser address bar domain. |
| **3** | **A genuine QR copied onto another person's forged document** | Signed payload cryptographically binds student name, degree programme, and issue date; verification result displays these fields prominently side-by-side for human visual comparison. | `test_threat_03_qr_payload_binding_mismatch.py` | A careless verifier who inspects only the green checkmark icon without checking whether the candidate name matches the physical document. |
| **4** | **Fake institution registers to issue convincing certificates** | Multi-tier onboarding workflow: manual platform admin approval, verification of government affiliation documents, official domain DNS check (`/.well-known/sanad-keys.json`), and public approval status. | `test_threat_04_unapproved_institution_issuance_blocked.py` | A corrupt or deceived human platform administrator approving fraudulent institutions despite paperwork irregularities. |
| **5** | **Dishonest or bribed registrar issues a bogus certificate** | Cryptographic audit trail: every issuance logs operator ID, timestamp, and client IP hash in append-only hash chain; Merkle batch roots prevent post-hoc deletion; fraud analytics flag anomalous volume. | `test_threat_05_audit_trail_tamper_evidence.py` | Cryptography cannot detect a genuinely signed falsehood. If authorized keys issue a bogus credential, it is valid until revoked. |
| **6** | **Issuer signing key stolen or compromised** | Per-institution key isolation; key lifecycle states (`active`, `retired`, `compromised`); certificates verified against key state; anchored timestamp proves pre-compromise validity. | `test_threat_06_compromised_key_window.py` | Certificates issued by an adversary during the window between key exfiltration and compromise notification. |
| **7** | **Replay of a revoked or expired certificate** | Real-time revocation lookup on every verification; Merkle transparency batch includes revocation events; signed JSON revocation lists served with HTTP cache expiry. | `test_threat_07_revocation_enforcement.py` | An offline verifier inspecting cached verification responses; interface displays explicit cache age timestamp. |
| **8** | **Database administrator maliciously edits a database record** | Signed payload is stored immutably; verification always recomputes hash and validates Ed25519 signature dynamically; external batch roots make silent DB tampering detectable. | `test_threat_08_database_mutation_detection.py` | A malicious DBA who also obtains unauthorized access to the institution's private key encryption key (KEK). |
| **9** | **Scraping certificate IDs to harvest personal records** | Certificate IDs carry >= 80 bits of cryptographic entropy; strict per-IP rate limiting; public view returns minimal fields; holder-governed selective disclosure shares. | `test_threat_09_certificate_id_entropy_and_rate_limit.py` | Targeted lookup by an adversary who already obtained the exact unique certificate URL or identifier. |
| **10** | **AI-generated or Photoshopped scan with convincing seal** | Road B never claims cryptographic proof; quality gate filters blurry scans; 5 forensic algorithms (copy-move, noise residual, glyph analysis, metadata, seal similarity) cross-evaluate; registry check mandatory. | `test_threat_10_forensic_pipeline_detection.py` | Heuristic false negatives on highly sophisticated synthetic images; residual risk managed by explicit advisory disclaimer. |
| **11** | **Flooding / DoS against the verify endpoint** | Strict rate limiting per client IP; token bucket for public endpoints; asynchronous Redis queue for heavy Road B CV/OCR jobs with tight execution timeouts. | `test_threat_11_verify_endpoint_rate_limiting.py` | Volumetric distributed denial-of-service (DDoS) exceeding application ingress bandwidth (requires edge/WAF mitigation). |
